# 学习机构词库消融测试

去掉12,277条学习机构词库后，r65在同一批52,146条记录上与固定v3参考的一致率从99.8485%降到82.3457%，下降17.5028个百分点。当前高一致率明显依赖这份词库；下降主要体现为无法确定边界，另有580条确定输出偏离参考。

## 脚本检查与补充

检查对象是用户下载的`/Users/tristana/Downloads/Edge/name_extractor_ablation.py`，仓库基线为`c38b991`、r65、固定参考v3。

原脚本核心方法正确：复制提取器及歧义资源到临时目录，将机构JSON写为空列表后重新加载模块。机构前缀、父机构集合、匹配树都会随导入重新构建，因而不是只清空一个变量、仍沿用旧匹配缓存。两组提取均只接收标题；固定参考只参与评分。

原脚本已经正确按原始行数加权，排除参考未决项的匹配计数，并检查原版能否重现r65。没有发现影响本次核心数值的计算错误。其不足是未显式确认参考版本及原始行身份覆盖、未调用独立输出合同检查、未细分确定分歧与弃权。

仓库中的`scripts/name_extractor_ablation.py`保留原实现并补充以上检查、逐行差异和两种分母的指标。另修正“独立v3参考”的措辞：本实验使用固定参考，不能证明其与词库研发完全独立。

验证结果：

- 3项实验测试通过：清空资源后匹配树重新构建；保留通用规则和歧义资源；参考未决、脚本弃权、确定分歧及无效输出正确区分。
- 全量46,760个去重标题映射到52,146条原始记录；原始行无重复、无缺失，参考均为v3。
- 原版实际重跑的姓名、状态、展示与字数全部重现冻结r65；两组输出合同失败均为0。
- 原下载脚本也单独运行完成，其全部共享核心指标与补充版本一致。
- 回读差异明细：9,156条、9,054个标题，原始行身份唯一，统计相符。

## 全量结果

以下均按原始52,146条记录统计，参考未决的3条保留在全量分母中、不计为正确。

| 指标 | 完整词库 | 去掉学习词库 |
|---|---:|---:|
| 运行时机构锚点数 | 12,359 | 82 |
| 与固定参考匹配 | 52,067 | 42,940 |
| 全量参考一致率 | 99.8485% | 82.3457% |
| 已确定输出（姓名或无姓名） | 52,067 | 43,520 |
| 提到姓名状态 | 51,309 | 42,781 |

9,127条原本匹配的记录在消融后不再匹配，没有原本不匹配的记录恢复匹配。其中8,547条由确定转为未决，580条仍确定但发生参考分歧；571条姓名或状态分歧、9条人数或拆分分歧。

合计9,054个标题、9,156条记录的状态或姓名候选发生变化。它比失去参考匹配的9,127条多29条，因为29条原本未决记录仅改变候选姓名，仍然未决。未决中的候选不是可直接写入生产Excel的已确认姓名。

只看消融后仍给出确定答案的43,520条，参考一致率为98.6673%。这个条件指标不能替代82.3457%的全量一致率，也不能把未决记录排除后宣称达标。

## 结论与范围

本次证据支持“当前r65对学习机构词库有明显依赖”。不能只把99.8485%解释为通用结构规则的能力。

去词库组保留82个内置锚点，其中包含具体机构名和地区词；还保留岗位、机构后缀、其他现有规则及`title_ambiguities_r61.json`。因此82.3457%也不是完全去掉数据知识后的纯通用规则成绩。

实验只测已有数据上的词库贡献，没有训练/测试隔离，也没有按陌生机构分组测试。它不能给出真实准确率，不能单独判定是否违反业务要求，也不能证明对新数据的泛化能力。没有调用AI重审，没有修改生产提取器、词库、固定参考或Excel，原验收状态保持不变。

复现：在仓库根目录运行`uv run python -B scripts/name_extractor_ablation.py`。

结果文件：`summary.json`为指标，`changed_titles.csv`为去重标题差异，`changed_rows.jsonl`为原始行差异及参考分类。
