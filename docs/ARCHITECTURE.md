# 系统结构

## 当前结构

项目尚未实现，目前只有输入材料和项目文档，没有代码模块、运行入口或依赖环境。

| 材料 | 职责 |
| --- | --- |
| `项目要求.md` | 定义提取范围、输出、验收和迭代要求 |
| `任职资格批复汇总测试.xlsx` | 待处理原表，内容尚未读取 |
| `行政批复高管姓名提取方案（简化提示版本）.docx` | 提示词方案写作范本，内容尚未读取 |
| `docs/` | 记录项目现状、结构、计划和决定 |

## 要求支持的流程（待实现）

本人编写并修订 Word 提取方案 → Codex 根据逻辑生成脚本 → 脚本从符合条件的标题提取姓名 → 在原表增加两列 → 校验结果并修正方案 → 人工检查 → 交付。

具体提取算法、编程语言、依赖管理工具、代码模块和校验方法尚未确定。按现有要求描述的规模，这是批量文本提取任务，当前没有高性能计算或分布式处理需求；性能是否需要优化，以后续实测为准。

## 数据约束

- “批复类型”用于确定处理范围，只从“标题”提取姓名，不读取正文。
- 输出保留原有记录和字段，只新增“提取姓名”“姓名字数”。
- 实际批量处理由脚本完成，不由大模型逐条提取。

完整约束见 [项目要求](../项目要求.md)。
