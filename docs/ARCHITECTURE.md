# 系统结构

## 当前实现

Python 3.13、uv 和项目本地 `.venv` 沿用现有依赖流程。openpyxl 读取标题，Excel 写回使用标准库 ZIP/XML。0.1.0 / r29及0.2.0 / r38已冻结；当前规则为0.3.0 / r44，生产出口与AI验证分离。

| 模块 | 职责 |
| --- | --- |
| `scripts/extract.py` | r44标题规则，输出姓名片段、状态、规则和疑点；不读取AI答案 |
| `scripts/institution_anchors_r41.json` | 当前12,271个机构片段，加82个基础锚点，实际12,353；r36原资源完整沿用 |
| `scripts/validate.py` | 不导入提取器，独立检查片段、顺序、展示、字数、状态及结构风险 |
| `scripts/pilot.py` | 标题去重、原行映射、实验持久化和历史匹配集合回归 |
| `scripts/full.py` | 全量运行、版本差异、盲队列、参考缓存及更正、冻结样本评价；`finish()` 只生成脚本逐行输入和参考比较；`export` 沿用原导出器 |
| `scripts/excel_output.py` | 在原 OOXML 追加 N/O 两列，独立核对原值、类型、格式、结构及新增结果 |
| `validation/v1/` | Git 保存的脚本全量快照、AI 共识与排除项、参考更正、机构来源、冻结样本和统计 |
| `tests/` | 20项业务、静默错误、历史风险、跨阶段参考处理与Excel保留测试 |

## 数据与现有流程

Sheet1 标题位于 A 列，数据行 2—52,147，共 52,146 条记录、13 个原字段。完全相同标题去重为 46,760 个，内部保存全部原行号，最终逐行映射。原 max_row 为 1,048,576、XML 行 107,328（含格式行），不作为业务记录数。

提取线：原标题 → `extract()` → 全量脚本结果及独立检查 → `validation/0.3.0/script-r44.jsonl`。当前121标题/130原行未决；r38的168/177为相邻基线，r29的812/871用于长期比较。

AI验证线：原标题与口径 → A/B独立上下文判断 → 首答及显式更正 → 共识参考或排除项。0.1.0使用同一gpt-6.1-sol/max；0.2.0及0.3.0新增判断使用同一gpt-6.1-sol/medium的独立上下文，只接收标题和口径，不看脚本答案或彼此答案。

当前生产出口：脚本结果 → `production_records()` → `excel-records.jsonl` → 原OOXML追加；姓名/字数取脚本值，无姓名空/0，未决空/空。AI旁路经`comparison_state()`写审计：匹配、确定差异、无姓名争议、脚本未决及参考缺失/无效/单渠道/分歧。脚本输出合同失败中止导出，不用AI替换。

0.1.0混合实验出口保留为历史，20标题/22行未决不能代表当前脚本能力。0.2.0新增独立A/B为gpt-6.1-sol/medium，只读标题和口径；0.1.0既有标签模型配置属于历史。

正文仅参与原表保留比较，不参与提取或标注。不同人全角分号连接；同人的双语表达保留原文大小写、空格和标点。字数计算汉字（含扩展）与 ASCII 字母，不计标点和连接词。

## 机构锚点及历史资源

Institution Anchors是机构边界词库，不是姓名表。锚点来自有效A/B共识支持的原标题：包括姓名前后的机构片段、明确岗位前的机构简称，以及无姓名参考支持的完整机构及分支。泛银行词和弱地区词不能可靠猜切，无法确定则留未决。机构来源另存`validation/0.3.0/institution-anchors-r41-sources.json`；未揭示的8个新验证标题排除于学习。数据机构词仍不能证明对新机构的泛化。

当前仅`institution_anchors_r41.json`被显式读取，r36文件继续保留作0.2.0历史资源。r29资源可从`validation/archive/0.2.0-rounds.zip`或0.1.0提交`5ed9094`恢复。机构括注与标题同时屏蔽且保留原偏移，掩码只在加载时计算一次。r18、r19、r22、r28等早期资源不参与当前运行，重跑历史源码须使用对应资源。

`full.py run` 会保存当前源码及实际读取的词库。逐轮历史归档不参与当前运行；r37 盲测冻结源码及其 r36 资源仍保留在 `validation/v2/`。

## AI 参考与统计边界

`validation/v1/ai-references.jsonl` 保存 23,387 个有效共识参考，与脚本快照分开；`ai-reference-exclusions.jsonl` 保存 35 个单渠道和 20 个分歧 / 未决标题，不能作为确定答案。5 条更正保留 before/after、理由和来源；首次原始标签仍在 `.local/`。

比较时同时检查姓名列表、展示值、字数与状态。r44在固定0.1.0共识范围内匹配23,287、未决100、确定差异0；r38的23,235/152/0保留作相邻基线。r38两个匹配因外文逗号转未决，另存降级记录。其余标题属于单渠道、参考分歧或未覆盖，不能计正确；回归参考已用于调规则，不是准确率真值。

现有缓存按精确标题/原行标识复用，来源失败、缺失、语义分歧不按多数票关闭。旧五组各400和0.2.0的100个普通标题均作为工程回归。0.3.0新增8个独立原始结构筛出的未用标题，仅覆盖缺少标准后缀、文号字符和重复尾句；冻结r43及实际资源后盲判断，8条全匹配，揭示后转回归。没有新的多机构、连接词或中外文复杂样本。

## Excel 与证据

现有导出器接受逐原行的 `row/name/length`；姓名正常填值，无姓名空 / 0，未决空 / 空。不新增结果工作表或其他 Excel 字段，风险另存审计和 CSV。

OOXML 追加保留原 A—M 单元格、行属性及其他 ZIP 成员，仅扩展维度 / 筛选至 O 并设置新增列宽。历史混合副本已逐项验证 52,146 记录、677,898 原字段位置、原值 / 类型 / 格式和结构，新增两列与当时混合输入一致；这种机械验证不能证明纯脚本提取正确。

`.local/`被Git忽略，保存历史、事前Word副本、辅助脚本及渲染；`validation/v1/`是保留的0.1.0基线。`run()`从它读取标题映射，默认工作目录为`validation/0.3.0/`，首个新轮次比较r38，后续比较前一新规则轮次；本阶段总变化另存`changes-from-0.2.0-r38.jsonl`。`labels()`依次复用0.1.0参考及排除项、0.2.0首答和0.3.0新判断；语义冲突仍未决，新增覆盖只统计本阶段新标题。默认Excel保存到`outputs/0.3.0/`，旧成果不覆盖。

0.2.0首答、字段规范化记录、全量与r37冻结快照继续保存在`validation/v2/`，逐轮历史在Git保存的`validation/archive/0.2.0-rounds.zip`，旧本地历史在未随Git保存的`.local/archive/0.2.0-local-history.zip`。0.3.0逐轮源码、结果、资源、迁移、冻结证据、标签和报告另存`validation/0.3.0/`。准确率未评估、人工检查未执行，不能把阶段版本和机械验证当作最终验收。
