# 0.6.0 迭代计划：人工反馈驱动的机构边界与姓名切分改进

日期：2026年10月12日。

状态：工程阶段已按本计划实施，当前0.6.0/r60待最终人工复核；详见[阶段报告](../validation/0.6.0/验证报告.md)。下文保留制定计划时的基线和设计依据，不是全量语义验收通过的最终方案。

## 1. 阶段目标与依据

0.6.0 从用户已填写的 122 个未决标题人工复核表出发，将反馈归纳为可解释、可验证的规则问题。优先解决机构起点和明确并列关系，再评估姓氏辅助切分、长姓名及外文姓名的处理。继续沿用现有脚本和验证流程，不整体重写提取器。

本阶段的目标是可靠解决固定数据中的实际问题，并检查修改是否影响原有正确结果。未决数量下降必须有正确性依据，不能用更积极的猜测代替改进。

依据按以下顺序使用：

1. [项目要求](../项目要求.md)及其中的原始邮件。
2. 用户本次明确提出的人工复核方式、机构热词和姓名切分方向。
3. 人工复核表、r56 冻结结果及实际标题。
4. 现有代码、历史回归和独立验证记录。

生产提取仍只读取标题。用户查看正文得到的姓名可以作为核验参考，帮助发现错误或解释风险；正文不能成为生产脚本的输入，也不能借正文答案建立逐标题姓名回填表。

## 4. 人工证据如何进入规则改进

### 4.1 先归类，避免直接把人工表变成答案表

按原 Excel 行号及完整标题对齐 r56，保留 C、D、E 原值，派生本轮人工更新判断。对每条记录分别回答：

1. 人工认为正确的姓名是什么，还是无姓名、标题异常或仍不确定？
2. 这个判断有何标题依据？是否依赖正文，或证据来源尚不明确？
3. 脚本的问题是机构边界、连接词、连续姓名、岗位、字符还是其他结构？
4. 可以提炼什么通用条件？该条件可能误伤什么标题？

证据至少区分四种：

| 证据类别 | 含义 | 用途 |
| --- | --- | --- |
| 标题可支持 | 能明确指出标题中的机构、岗位、人数或并列边界 | 规则诊断、回归及变化复核 |
| 正文辅助确认 | 正文能确定真实姓名，但标题自身的边界还需判断 | 错误核验和歧义分析，不提供运行时答案 |
| 来源尚不明确 | 有人工姓名判断，但没有足够依据说明 | 暂作候选，不能自动升级为确定真值 |
| 仍有争议或异常 | 已表达疑问，或标题残缺、字符不可辨 | 保留未决并说明原因 |

正文辅助确认不使该记录失去核验价值。它仍可检验一个标题规则是否产生错误；只是不能因为知道正文答案，就声称标题已经提供了充分边界。

### 4.2 真实歧义需要具体解释

对继续未决的标题，记录实际可成立的解释、各自的标题依据以及缺少的信息。例如“何子任高级管理人员”需要检查“何子任”完整姓名与“何子＋任＋高级管理人员”两种边界。

不能仅因为名字较长、陌生、四个字或字典不收录，就认定存在真实歧义；也不能仅因为理论上可以任意切开，就将一个正常完整姓名降为未决。

“标题异常”与“确定无姓名”分开。标题只剩“关于”不等于确认该批复没有姓名；普通新闻或确实没有明示姓名的机构事项，才可以在标题依据充分时归为无姓名。

## 5. 机构边界改进

### 5.1 采用完整机构类型词，限制使用位置

“村镇银行”可以作为机构类型线索，但不能建立“遇到村镇就截断”的全局规则。优先利用现有完整机构锚点，再检查泛称机构与岗位形成的标题模板。

拟处理的直接结构是：许可动词＋姓名候选＋村镇银行＋明确岗位＋任职资格。例如“关于核准钱建东村镇银行董事任职资格的批复”。实施时检查姓名候选、岗位和尾文是否完整，以及是否存在另一种机构起点。

完整机构优先于机构类型后缀。遇到“林长沙翔安民生村镇银行”，应识别“翔安民生村镇银行”，留下“林长沙”；不能留下“林长沙翔安民生”，也不能再按常见姓名长度截成“林长”。

### 5.2 机构资源与通用规则分别维护

- 可反复使用的完整机构片段沿用现有机构锚点资源机制，记录原标题和依据。
- “村镇银行”“农村商业银行”等泛称机构词，按完整模板处理，不能因为词表出现就认为其左侧全部是姓名。
- 新机构片段如果来自正文，应另标来源，不把它记为独立标题盲参考；采用前检查标题中的实际表达和全量命中情况。
- 不添加“某行号输出某姓名”或“某标题直接返回某姓名”的分支。

本轮需要重点检验“逯晓利村镇银行”这类 D 列仍有疑问的记录。新增类型词不能自动把所有相似前缀都认定为人名。

### 5.3 正例、反例与验证

正例覆盖泛称机构、带地名和品牌的完整机构、机构在姓名前后、机构后跟多人等不同位置。反例包括完整机构内部含“村镇银行”、纯机构岗位没有姓名，以及机构前后均可能有主体的标题。

优先复用真实标题，例如既有回归中的“袁斯佳井冈山九银村镇银行有限公司计划财务部负责人”。必要的合成反例只验证规则边界，不计作真实数据准确率或已解决原行。

每次调整先查新机构规则的全量命中及变化标题，检查是否将地名、品牌、分支或部门误留在姓名中。

## 6. 人名排列、连接词和姓氏辅助切分

### 6.1 分开处理不同排列方式

| 标题结构 | 拟处理方式 | 重点风险 |
| --- | --- | --- |
| 明确顿号或分号名单 | 按括号外分隔及完整片段处理 | 括号内别名、岗位分隔不能被误拆 |
| A 和/及/与 B | 检查连接字两侧是否处于姓名槽位，并结合人数、并列形式和主体结构 | 和、及、与可能属于姓名、机构或部门 |
| 姓名与完整岗位子句并列 | 沿用完整子句解析，消费全部主体 | 首个岗位不能吞掉后面的姓名 |
| 连写姓名，没有分隔 | 提出多种候选，结合结构和辅助词表验证 | 姓氏和长度不足以证明人数 |
| A、B 等 N 人 | 只输出标题中明示的姓名 | 不能补齐未写出的其他人员 |

优先处理“孙刚与谭雅俊”“杨宝秀和孟光”“陈远、王宝刚及顾弘”等明确并列候选，检查现有规则是否过度弃权。同时保留“周友和谷政”的反例：不能将“和”机械并入“周友和”，也不能把所有姓名中的“和”都作为连接词。

连接词两侧看起来都像姓名，只能形成候选，还应检查完整机构、岗位、括号、人数和其他标题解释。不同连接结构可有不同接受条件，不设一个仅凭字数的通用通过阈值。

### 6.2 姓氏词表的定位

本阶段拟评估姓氏词表，现行 r56 没有该资源。词表的用途是发现可能的起点、提出连写姓名切分候选并解释候选，不作为姓名白名单。

资源需区分单姓和复姓，记录实际来源和覆盖范围。常见姓氏可以先用于小范围实验，低频姓氏或未收录姓名不能被直接判错。复姓也不是无条件最长匹配：有其他结构解释时仍须保留竞争候选。

候选示例：“彭一桅胡明清”可能形成“彭一桅｜胡明清”；“殷熊毅辉”即使能够构造两段，也不能据此否定完整四字姓名。两三字长度只作为常见形态线索，不是允许长度范围。

姓氏辅助规则按以下顺序评估：

1. 从机构、岗位及许可动作中确定姓名候选范围。
2. 保留整个候选片段，并生成有姓氏依据的可能切分；考虑复姓。
3. 检查各方案是否消费全部姓名片段，是否符合明确人数或并列证据。
4. 用本轮人工案例和误伤反例验证，比较新增解决与新增错误。
5. 只有足够的标题依据支持结果时确认；算法只找到一个候选，不等于语义只有一种解释。

不引入没有验证依据的置信分数或分数阈值。若姓氏词表只增加猜测、不能在真实标题中提供可靠收益，就只用于疑点说明，不进入生产确定条件。

### 6.3 需要保留的反例

- 王夏春子、殷熊毅辉、王菲米兰：四字姓名不能按 2＋2 自动拆分。
- 何子任、刘任、侯琳任绥芬河：同一个“任”字可能处于不同边界。
- 郑和、刘金和、孟和巴拉及既有机构部门连接字：姓名或其他字段内部的“和”不能统一切开。
- 姓氏词表没有收录的完整姓名：不得直接转为无姓名或错误。
- 复姓、少见姓氏、长姓名和多个岗位：字数与岗位数量均不能单独证明人数。

## 7. 长姓名、少数民族姓名及汉字音译姓名

本阶段处理姓名的书写结构，不根据姓名推断当事人的民族或国籍。不能用常见汉族姓名模式约束所有汉字姓名。

“格根陶力古尔”“阿拉腾础鲁”“森山健太郎”等片段，应先检查姓名槽位和完整机构岗位边界。长姓名整体保留、多人连写拆分是两种不同结果，不能靠“超过四字”统一决定。

现有 `_finish()` 对超过四字的连续汉字保留候选并弃权，本阶段需结合 41 个以长连续片段为未决原因的标题，区分真正连写多人、完整长姓名、未切净机构和其他结构问题；这 41 个不是 41 个已知错误。

拟改进原则：

- 中点及其他姓名内部连接符保留，不作为不同人的分隔符。
- 不因没有常见姓氏就否定完整姓名。
- 先修机构和岗位残片，避免将边界失败误归为“名字太长”。
- 明确人数、完整并列结构和标题中的其他证据优先；无充分依据时保留原片段及具体疑问。
- “董事、董事会秘书”等多个职务不能推导出两个人。“韩豪日钦夫”一条仍需检查 D 列的人数疑问，不自动关闭。

已有 `title_ambiguities_r55.json` 的七条弃权记录保留来源。对真实条目重新判断时需说明标题依据和原争议如何消除，不能因为正文知道正确姓名或为了减少未决，批量删除弃权保护。

## 8. 外文姓名与双语表达

### 8.1 以完整姓名表达为单位

目标是提取一个人的完整姓名，不拆分其姓、名、中间名或中文别名。不按空格、逗号、连字符、中点或大小写单独判断人数。

以下完整表达均作为本阶段同人候选的核验样例，保留原标题中的实际书写：

- `DAUNYSandrine，Marie-José`
- `SURIKOV，ARTEM`
- `BaronvonPfetten，JeanChristophe`
- `DESPLATS-REDIER，Jean-CédricLaurent（赛德瑞）`
- `Stéphanie,Anne,MarieLEGALdeKERANGALép.CLEMENTDEGIVRY`

此前原表正文核验支持这些表达对应同一人，但是否可以由通用标题规则确认，需要在本阶段另行验证，不能直接用正文结论撤销现有外文逗号弃权。

### 8.2 具体处理要求

- 先利用完整机构和岗位确定外文姓名范围；机构括号与姓名别名括号分别处理。
- 保留实际大小写、重音字符、逗号、连字符、空格及中文别名；不凭正文补回标题没有的空格或姓名字符。
- 括号内中文别名与外文姓名属于同一个人的表达时整体输出，不重复计为第二人。
- 不将外文逗号统一转换为分号。确有多人时，仍需人数、明确名单或分别的任职子句等支持。
- 姓名字数沿用现有口径：汉字和 ASCII 字母计数，标点、连接符和空格不计；重音字符不在本阶段擅自改变计数合同。

保持已有双语、中点及外文回归样例。只有真实案例证明现有字符或计数口径不足，才单独记录并处理该问题。

背景参考：[W3C 姓名处理指南](https://www.w3.org/TR/international-specs/#working-with-personal-names)。该指南说明姓名组成与顺序多样，不是本项目自动判定单人或多人的规则来源。

## 9. 独特问题及暂不自动解决的案例

| 问题 | 处理计划 | 禁止的捷径 |
| --- | --- | --- |
| 裸“核准某某的批复” | 检查标题语义是否足以判断个人；人工或正文结论另存 | 只因像常见姓名就确认 |
| “核钟丽华”“邱畅殷拟任职资格” | 分析缺字或许可动词与姓名边界 | 只因钟是常见姓就删掉前面的核 |
| “行舒振国” | 检查机构、岗位残片及姓名首字两种解释 | 无依据删除行字 |
| “陈” | 区分原字符异常与显示字体问题，保留原字符并说明限制 | 用正文中的“龚”替换原标题字符 |
| “关于”等残缺标题 | 保留异常及原行映射，无法提取则未决 | 当作正常无姓名或借正文补姓名 |
| “不予核准”等否定许可 | 仍提取标题明示的被批复人，保留动作语义 | 因未批准就认定没有姓名 |

不强行解决每个独特案例。与共性修复没有直接关系的疑点，记录具体原因后保留，避免为单条未决建立脆弱分支。

## 11. 验证与人工检查

### 11.1 逐轮验证

每个问题族修改后执行：

1. 真实正例与可能误伤的反例回归；补充必要测试，不机械扩充合成题数量。
2. 46,760 去重标题全量运行，映射仍为 52,146 原行。
3. 对 r56 和上一轮分别比较姓名、状态、展示及字数。
4. 检查所有真实变化标题，记录接受、错误、需继续判断或合理转未决。
5. 复用已有独立输出合同和历史参考。新规则与历史参考冲突时核对来源，不自动改标签迎合脚本。

只有规则相关验证通过后继续下一问题族。最终跑现有完整测试集；普通文档整理不要求运行提取和测试。

### 11.2 本轮定向人工复核

- 复核原 122 个未决标题的更新结果，特别是 E 列更正和 D 列仍有疑问的案例。
- 对所有变化标题逐条复核，包含原来已经输出姓名或确认无姓名的记录。
- 复核 694 个原“无姓名”去重标题，并映射其 761 原行；这项工作尚未完成。
- 补查受本轮规则影响的多人、机构前后主体、括号、外文、长姓名及复杂岗位。

记录标题判断和正文辅助核验来源。检查过但仍无法判断的条目不能记为通过。发现的问题用于修规则后，该记录属于诊断或回归样本。

### 11.3 冻结随机人工抽查

建议在本轮改规则前，从 r56 已提取姓名的去重标题中固定抽取 200 个，保存名单和随机种子，提供完整标题用于人工独立判断，隐藏脚本及 AI 答案。与定向案例分开记录。

该 200 个标题是本阶段建议规模，执行时可按实际时间调整，并报告实际样本数、覆盖类别及抽样单位。不能将去重标题抽样结果直接换算成原行总体准确率。

作为本轮独立检查的随机样本，不用于调参。如果发现问题并将其用于修规则，如实将该样本记为已揭示回归材料；修后复测不再计为独立准确率证据。只有确需进一步总体质量判断时，才另安排未揭示样本，避免无限抽样。

随机抽查用于了解整体质量，定向检查用于找错。200 条即使全部正确，也不足以证明总体准确率超过 99.8%，更不能证明所有未检查标题都正确。

### 11.4 导出验证

沿用原 OOXML 追加 N/O 两列的导出方式，保持 52,146 原行、13 个原字段、原值和格式。不同人使用全角分号；同人的双语与外文表达保留原文。

状态与 Excel 输出保持区分：有姓名输出脚本姓名及字数；确定无姓名输出空姓名 / 0；未决输出空姓名 / 空字数。人工和 AI 参考不参与生产单元格填值。

## 12. 指标、验收与停止条件

### 12.1 核心指标

| 指标 | 定义 |
| --- | --- |
| 可靠解决的原行 | r56 未决，本轮确定，且实际复核支持结果的原行数量 |
| 纠正的原有错误 | r56 已确定输出被核实错误，本轮修正并复核正确的原行数量 |
| 引入的新错误 | r56 正确输出被本轮改错，或 r56 未决被本轮错误确认的原行数量 |
| 原有正确结果退为未决 | 原正确输出因新增条件弃权，单独说明原因和数量 |
| 仍未决 | 当前无法确认的去重标题及原行数，按具体原因归类 |
| 未复核变化 | 尚无充分复核结论的变化标题及原行数，不并入可靠解决 |

三个核心数均以原行为主，同时列去重标题数。将无姓名正确确认与有姓名正确提取分别报告；人工初答更正不计为生产错误修复。

### 12.3 最终项目验收与本阶段完成分开

项目仍要求准确率超过 99.8%、自查发现错误归零和交付前人工检查。按 52,146 原行计算，超过 99.8% 对应最多 104 行错误。

如果 131 未决原行全部计错，即使其他行全对，准确率上限也约为 99.7488%；至少可靠解决 27 行只是具备达标可能的必要条件，不是验收通过。已输出错误、新引入错误和尚无语义核验的部分仍会影响判断。

不能从“未决减少”“AI 一致”“测试通过”计算真实准确率。没有可靠总体真值时，报告已复核范围的结果、剩余证据缺口和保守条件，不填报没有依据的总体准确率。

### 12.4 停止与回退

- 共性问题族已完成必要修复和相称验证后，结束该轮，不扩大为所有未来姓名的通用研究。
- 某个条件发现误伤时，先修复或回退这个条件，再评估局部方案是否不足。
- 姓氏词表、长姓名和外文规则不能可靠消歧时，保留未决及具体解释。
- 后续真实反例再驱动下一步，不为缩小剩余数量增加逐标题答案例外。
