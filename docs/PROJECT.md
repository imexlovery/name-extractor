## 使用与复现

沿用Python/uv、项目本地`.venv`和`uv.lock`。

- `uv run python -B scripts/full.py run`：从Git保存的0.1.0标题映射全量运行并保存当前源码、实际机构资源、状态和变化。
- `uv run python -B scripts/full.py finish`：纯脚本逐原行Excel输入及独立AI比较，直接复用已提交0.1.0参考和排除项，再读取0.2.0新增盲标。无需历史`.local/`数据。
- `uv run python -B scripts/full.py export`：沿用原OOXML导出器生成0.2.0副本并核对原字段保留；可用`--output`指定副本。
- `uv run python -B -m unittest discover -s tests`：业务、已观察边界、回归、AI不回填和Excel保留测试。

`validation/v2/` 只保留 0.2.0 当前结果、r37 盲测冻结源码及结果、当前机构资源及来源、参考首答、字段规范化记录和交付报告。44 个逐轮源码、旧资源、统计及变化文件集中到随 Git 保存的 `validation/archive/0.2.0-rounds.zip`，归档内保留原相对路径；解压到独立目录即可查看，重跑历史提取器需使用对应资源。

本轮中间全量结果、Word 历史、辅助脚本及旧字节码偏差共 48 个文件收进 `.local/archive/0.2.0-local-history.zip`，未随 Git 保存。`.local/v2/` 仅保留最新 Word 与 Excel 显示核对材料，旧预览图及字体缓存已清理。详细 0.1.0 实验仍在 `.local/pilot-20261010/` 和 `.local/full-20261011/`。

原r29曾遇到旧字节码问题，本轮r34切换同长度资源名时再次发现并重跑；旧偏差保存在上述本地归档的`.local/v2/r34-stale-bytecode/`，重跑不计修改轮次。以上命令使用`-B`避免写入新缓存；当前已清理旧提取器字节码。Word中0.2.0修改前逐轮加入方案说明，历史0.1.0逐版表仍是收尾回填。
