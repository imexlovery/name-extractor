## 使用与复现

沿用Python/uv、本地`.venv`及`uv.lock`。

- `uv run python -B scripts/full.py run`：全量运行当前r44，保存源码、实际资源、状态及相邻规则轮次变化。
- `uv run python -B scripts/full.py finish`：复用Git保存的0.1.0固定参考、排除项及0.2.0新增首答，再读取0.3.0盲判断；输出纯脚本逐原行输入和比较。
- `uv run python -B scripts/full.py export`：沿用原OOXML导出器生成0.3.0副本，可用`--output`另指定路径。
- `uv run python -B -m unittest discover -s tests`：业务边界、历史风险、缓存继承、AI不回填和Excel保留测试。

默认读写`validation/0.3.0/`、导出`outputs/0.3.0/`。`--work`仅改变工作目录，重跑历史提取器仍需对应源码、资源和项目版本。已有当前全量快照时，重复`run`仍比较前一规则轮次，不把重跑记作新的修改。

0.1.0对应r29及Git `5ed9094`；0.2.0对应r38及Git `a539f58`；0.3.0对应r44。内部rNN为规则轮次，软件0.x.y为阶段版本，均不代表验收通过。0.1.0历史混合Excel的20标题/22行未决不作为纯脚本基线。

`validation/v1/`、`validation/v2/`、`outputs/v2/`及原附件保留。0.2.0逐轮历史仍在Git保存的`validation/archive/0.2.0-rounds.zip`，大体量旧本地历史在未随Git保存的`.local/archive/0.2.0-local-history.zip`。本轮每次先更新Word再修改规则，事前Word副本及渲染在未随Git保存的`.local/0.3.0/`；逐轮源码、实际资源、结果、迁移、首答和报告保存于`validation/0.3.0/`。根目录Word为当前方案，旧Word可从0.2.0 Git基线恢复。
